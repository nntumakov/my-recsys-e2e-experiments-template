## Standards

**S1, P2 — неполная проверка параметров DSL до HTTP. Исправлено.**
`FuzzyQueryConfig` принимал `distance=3`, тогда как поддержанный OpenSearch/Lucene
fuzzy edit distance ограничен 0–2. `LexicalQueryConfig` принимал любую непустую
строку minimum_should_match, включая `garbage`. Ошибки конфигурации обнаруживались
только после обращения к источнику, вопреки правилу проверки до внешних side effects.

Теперь constructor отклоняет неподдержанную дистанцию и проверяет синтаксис MSM:
целые числа, проценты, отрицательные формы и условные комбинации. Регрессии
в `test_jobboard_search.py` проверяют неверные значения и документированные формы,
включая `2<-25% 9<-3`. Повторный независимый review подтвердил закрытие S1.
Других существенных нарушений стандартов или архитектурных smells не подтверждено.

## Spec

**R1, P2 — fuzzy-защита повторённого слова теряла привязку к вхождению. Исправлено.**
Для `developr DEVELOPR` normalizer распознавал uppercase-сокращение, затем защищал
все совпадения нормализованного слова. В результате допустимое строчное вхождение
не получало fuzzy, нарушая §7.4 spec 004. После исправления normalizer регрессионный
тест выявил вторую часть той же проблемы: compiler хранил eligible слова по тексту,
что уже включало fuzzy и для защищённого повторения.

Теперь normalizer переводит позицию конкретного uppercase-вхождения в normalized
spans с учётом Unicode и пробелов, а compiler хранит eligibility по span. Проверены
строчный/uppercase повтор и NFKC/whitespace offsets. Повторный независимый review
подтвердил закрытие R1. Других существенных пропусков spec или расширения scope
не обнаружено.
