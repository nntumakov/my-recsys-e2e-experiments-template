# 002. Наполнение оставшегося каркаса

Статус: реализована; backend оставлен резервом по явному указанию пользователя. Сохраняются
исходные каталоги и абстракции. Spec 001 остаётся контрактом интерактивного поиска;
этот этап добавляет ранее отложенные локальные возможности и исправления review.

## Outcome

Можно собрать через Hydra обработку с ветками, объединить выдачи, оценить NDCG
по явной разметке и сравнить несколько pipelines на одинаковых входных данных.
CLI-поиск продолжает работать без метрик и разметки. Новые зависимости не нужны.

## Контракты

- `ListWiseNDCG(k).eval(serp, relevance)` принимает отображение id → неотрицательная
  конечная оценка релевантности. Search score не заменяет разметку. DCG использует
  `(2**grade - 1) / log2(rank + 1)`; IDCG строится по всей переданной разметке,
  включая не найденные документы. Оцениваются первые k позиций. Пропущенная
  разметка для оцениваемой позиции и повтор id в SERP — ошибка. При нулевом IDCG
  результат равен 0. Report содержит value, dcg, idcg и k. Переполнение gain
  отклоняется как ошибочное числовое представление: grades >= 1024 не поддерживаются.
  Малые положительные grades не обнуляются при вычитании единицы из gain.
- `summarize` считает count, mean, population standard deviation, min и max
  конечных значений. Пустой набор даёт count=0 и None у статистик, не искусственный 0.
- `FieldScoreExtractor(field)` переносит числовое поле item.fields в score.
  Проверяет все значения до изменения любого item; исходные fields сохраняются.
- `TopKTransformer(k)` сохраняет первые k items без перестановки и изменения
  документов. Коллекция сохраняет свой конкретный тип, фильтры и context не меняются.
- `BranchTransformer(branches)` получает имена веток → имена transformers.
  Ветки выполняются последовательно в порядке конфигурации на независимых deep
  copies. Все имена и копии подготавливаются до первого вызова. Неуспех ветки
  прекращает работу без публикации частичных результатов в родительский payload.
- `PipelineData.branches` — отдельное временное рабочее пространство ветвления,
  а не пользовательский контекст. Shallow copy копирует внешний mapping, deep
  copy рекурсивно изолирует ветки с сохранением общих immutable filters.
  Повторное ветвление при непустом workspace отклоняется; вложенный pipeline
  ветки должен завершить своё объединение до возврата.
- `ReciprocalRankFusionTransformer(rank_constant=60)` объединяет ветки по id:
  сумма `1 / (rank_constant + rank)` с позициями от 1. Duplicate id внутри одной
  ветки — ошибка. При совпадении id поля берутся из первой встретившейся записи;
  новый score — RRF. При равных итоговых score сохраняется порядок первого
  появления. После успеха родитель получает SERP, workspace очищается. Parent
  filters неизменны; добавленные фильтры веток имеют только локальную область.
- Registry проверяет ссылки/циклы как последовательных pipelines, так и
  BranchTransformer при сборке. Автоматическая параллелизация не вводится.
- `ComparisonCase` содержит key, исходный PipelineData и relevance.
  `CompareExperiment` получает именованные pipelines, cases, metrics и exporters.
  Для каждой пары case/pipeline использует независимую копию входа. Результат
  содержит полные выдачи, отчёты метрик и статистику по каждой паре pipeline/metric.
  Это описательное сравнение, без significance tests и автоматического выбора победителя.
  Пустые cases/pipelines/metrics, дубли case keys и неверные ссылки отклоняются
  до исполнения. Любая ошибка прекращает эксперимент и не вызывает exporters.

## Границы

Backend client оставлен пустым резервом по явному указанию пользователя
«Ничего не пиши» в ответ на вопрос об этой интеграции. Его реализация не входит
в текущую поставку; OpenSearch-протокол принадлежит `integrations/opensearch`.
Абстрактные методы и классы-маркеры не заполняются фиктивным поведением.
Пустой package __init__ сам по себе не считается незавершённой функцией.

## Verification

Проверяются известные значения NDCG, missing judgments, IDCG по всему набору,
duplicate ids, нулевые gains и cutoff; статистика пустой/непустой выборки;
атомарность extractor, независимость веток, failure до публикации, RRF и ties;
реальная Hydra-композиция локального сравнения с экспортом полного артефакта.
Все gates spec 001 продолжают проходить. Review regressions покрывают пустые URL
delimiters, nonfinite JSON и cleanup failure без подмены исхода публикации.

## Evidence текущей реализации

  ссылок до вызовов, подготовка копий до исполнения, остановка на ошибке,
  отклонение необъединённой вложенной ветки, циклы, RRF/ties, extractor и top-k.
- `tests/test_evaluation.py`: NDCG по полному набору judgments, cutoff,

  при ошибке метрики, Hydra instantiate с настоящим JSONExporter.

  реальный subprocess с документированной заменой Hydra experiment, без поиска.
- Полный набор на 2026-09-19: 93 теста; Ruff check, Ruff format --check,
