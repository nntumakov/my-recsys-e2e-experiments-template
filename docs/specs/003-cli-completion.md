# 003. Завершение каркаса и запуск через Poetry

Статус: реализована и проверена локально. Evidence — в
[development.md](../development.md).

## Результат и границы

Все модули `src` имеют определённую роль; конкретные компоненты реализуют
контракты specs 001–002. Абстрактные методы остаются абстрактными, доменные
специализации наследуют поведение, package-модули документируют свою область.
Backend остаётся резервом без сетевого протокола и без фиктивной реализации.

Poetry 2.2+ становится единственным документированным способом установки и
запуска: `poetry install`, `poetry run python -m src.run`. Проект запускается
из checkout без публикации Python-пакета. Hydra и существующие форматы
конфигурации, запросов и JSON-артефактов сохраняются. `poetry.lock` заменяет
`uv.lock`; runtime-зависимости остаются прежними.

Исходный замысел переносится из `src/ZERO-SPEC.md` в `docs/ZERO-SPEC.md`.
README отвечает за запуск, architecture — за контракты, development — за
готовность и проверенные ограничения. Все ссылки обновляются.

## Согласованность и ошибки

Интерактивный эксперимент, как и сравнение, принимает завершённую SERP.
Необъединённые ветки или другая коллекция означают ошибку pipeline:
эксперимент не печатает успешную выдачу и не экспортирует артефакт.
Остальные failure semantics specs 001–002 сохраняются.

## Приёмка

- Проверить каждый Python-модуль `src`, включая наследуемое поведение,
  абстрактные интерфейсы и владельцев композиции.
- Poetry проверяет manifest/lock и устанавливает зависимости.
- Через Poetry проходят Ruff, format, ty и весь pytest.
- Реальный `poetry run python -m src.run` против локального HTTP-сервера:
  два запроса, EOF, полные документы и сохранённый JSON; ошибка запроса
  прекращает сессию без артефакта. Локальное сравнение также запускается.
- Регрессия незавершённого pipeline проверяет отсутствие вывода и экспорта.
- Проверены ссылки документации и `git diff --check`.

Backend остаётся вне области spec; live OpenSearch smoke выполняется отдельно.
