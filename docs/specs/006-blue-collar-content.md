# 006A. Русскоязычный контент для рабочих профессий

Статус: **обязательное приложение к spec 006; контент реализован и проверен локально**.
Дата: 2026-09-29. Первый профиль — русскоязычные рабочие профессии. [Основная spec](006-query-and-painless-candidates.md) читается
вместе с этим приложением. При расхождении примеров и объёмов это приложение
задаёт первый профиль и обязательное наполнение; пять экспериментов сохраняются.

## 1. Что должно быть готово сразу

Новый профиль `blue-collar/ru` поставляется полностью наполненным и выбирается
по умолчанию в новом research notebook и wrappers spec 006. Глобальный `main`
и существующие RU/EN/IT эксперименты не меняются. Англоязычные технологии остаются
регрессиями, а не основным материалом сессии с продактом.

| Контент | Минимальный объём и смысл |
| --- | --- |
| Профессии | 64 самостоятельных понятия из перечня ниже |
| Распознаваемые формы профессий | ≥320 уникальных пар concept/surface; не требуется 5 ложных синонимов каждой роли |
| Навыки/оборудование/процессы | ≥40 понятий, в том числе перечисленные ниже |
| Квалификации | ≥16 значений/понятий: категории транспорта, разряды, допуски, удостоверения |
| Опыт, график, занятость, условия | ≥32 понятия суммарно; отдельные типы, не всё в seniority |
| География | ≥20 городов, ≥60 распознаваемых форм; без выдуманных районов/координат |
| Curated rewrites | ≥40 явных направленных правил; 30 пар ниже + ≥10 контекстных вариантов |

| Контролируемые вакансии | ≥96 вымышленных карточек, все 8 семейств и metadata edge cases |
| Контрастные пары/тройки | ≥32 вручную описанные группы «почему порядок/допуск должен отличаться» |
| Notebook | Готовые подборки «склад», «водители», «производство», «торговля», «условия», «ошибки ввода» |

Количество не заменяет семантику: разные регистры, пробелы и `ё/е` не считаются
новыми понятиями. Словоформы, женские названия, разговорные формы — recognition
surfaces, а не автоматически expansion alternatives. На один concept в DSL по-прежнему
не более 4 форм. Большой словарь не означает огромный запрос.

Нельзя закрыть объём механическим декартовым произведением профессия×город.
Каждая запись имеет стабильный id, canonical, surfaces, отдельно разрешённые
alternatives с relation, ambiguity/context rules и author provenance.
Для starter provenance допустимо `curated-project-seed`: это рабочая поисковая
таксономия; официальная классификация и статистика реальных запросов не использовались.

## 3. Слоты, важные именно для рабочих профессий

Текущих role/skill/seniority/work_mode/location недостаточно. В новом профиле
явно добавляются типы `experience`, `schedule`, `employment`, `qualification`,
`work_condition`. Это часть реализации domain/parser/compiler/trace, не только YAML.
Не называть график seniority, вахту remote-work и медкнижку навыком.

| Тип | Обязательные примеры понятий/форм | Поведение |
| --- | --- | --- |
| experience | без опыта; с обучением; ученик; стажировка; опыт от года; опыт от 3 лет | Мягкие сигналы, не автоматический фильтр |
| schedule | 2/2; 5/2; 3/3; 6/1; сутки через трое; ночные смены; дневные смены; гибкий график; выходные дни | Мягкие предпочтения; значения не spellcheck-ятся |
| employment | полная занятость; частичная; подработка; сезонная; временная; вахта | Вахта — способ организации работы, не город |
| work_condition | проживание; питание; развозка; ежедневные выплаты; еженедельные выплаты; оформление по ТК; самозанятость; тёплый склад; холодный склад; на своём автомобиле | Мягкое текстовое свидетельство, не гарантия условия |
| qualification | категория B/C/CE/D; удостоверение тракториста-машиниста; НАКС; удостоверение охранника; медкнижка; разряды 2–6; группы электробезопасности II–V | Отдельные атомарные понятия; без ослабления/подмены категории |

Распознанные qualification-группы обязательны в **structured path**, а не входят
в округляемые 75% role/skill/residual coverage. Их нельзя отбросить ради допуска
других тем. Literal path сохраняет своё текстовое поведение: это не legal eligibility
filter для всей выдачи. Точный обязательный фильтр возможен только как явный filter
по подтверждённому полю индекса; notebook показывает это различие.

Вахтовые циклы `15/15`, `30/30`, `45/15`, `60/30` распознаются как schedule
в контексте вахты. Не объявлять `2/2` двумя годами опыта или дробью. `6 разряд`
и `6/1` — разные типы. B/В, C/С, CE/СЕ объединяются только в контексте
«водитель/категория/права», а не глобальной заменой латиницы и кириллицы.

Цельная распознанная роль имеет приоритет над целиком вложенным общим role/skill:
«водитель погрузчика» не становится ambiguous только из-за equipment «погрузчик»,
«повар горячего цеха» — из-за skill «горячий цех». Вложенный фрагмент виден в trace,
но не создаёт второй обязательной группы или двойного bonus. Раздельное «повар,
опыт в горячем цехе» сохраняет role+skill. Несогласованные пересечения и разные
понятия одной длины по-прежнему дают ambiguity. Это явная новая политика C4;
существующий `parsed` не меняется без opt-in.

`вахта`, `подработка`, `без опыта` без профессии: только literal query,
никакого match_all по attribute bonuses. В роли не угадывается «разнорабочий».

В стартовом профиле квалификация маршрутизируется в title/description,
optional qualifications text field при наличии; остальные новые атрибуты —
в description и optional conditions text field. Их наличие не обязательно:
все five presets для QU умеют работать только с title/description.
Новые optional fields задаются в source, не подставляются выдуманными именами.

## 4. Условия и отрицания: не обещать лишнего

Обязательные whitelist-фразы: «без опыта», «без опыта работы», «без стажа»;
они распознаются целиком как experience. Фразы «без проживания», «без медкнижки»,
«не вахта», «не ночные», «кроме доставки» **не whitelist**: отключают structured
expansion/rewrite и сохраняют literal с объяснением unsupported negation.
Нельзя удалить «без» и затем усилить противоположное условие «проживание».

Зарплатные запросы `от 80000`, `80 тысяч на руки`, `3500 за смену`,
`до 120000`, `ежедневно 4000` сохраняют числа, единицы и контекст в residual.
Диагностика отмечает `unsupported_salary_constraint`: числовой диапазон,
net/gross, валюта и период выплаты не компилируются в filters.
Маркер не удаляет исходные слова и не притворяется распознанной денежной моделью.
Числа, графики, категории и разряды не подвергаются spelling/layout correction.

Фразы «ищу работу», «работа», «вакансия», «срочно» не становятся новыми профессиями.
В первый профиль входит конечный список вводных фраз для **structured path**:
`ищу работу`, `ищу подработку`, `нужна работа`, `вакансия`, `требуется`.
Они помечаются отдельными nonsemantic spans и не входят в coverage; если phrase
содержит подработку, её employment hint сохраняется. Literal path исходной строки
не меняется. Удаление прочих неизвестных слов запрещено. Это явное дополнение
к правилу «residual сохраняется», с готовыми positive/negative cases.

## 5. C3 для первого рынка: график, а не remote-first

Вместо IT-примеров поставляются `day-first`, `night-first`, `shift-2-2-first`.
Одно confirmed keyword-поле `schedule_category` имеет согласованные mutually exclusive
значения fixture: `day`, `night`, `shift_2_2`, `other`. Maps задаются через params,
unknown/missing идут последними. Реальный mapping может отличаться и задаётся пользователем.
Эти buckets — только fixture-контракт, не утверждение, что дневная смена несовместима
с графиком 2/2 в реальной жизни. Если реальное поле multivalued/пересекается,
этот preset требует явной настройки подходящего признака, а не выбора первого значения.

В notebook: «хочу дневные смены» — явное переключение preset, не автоматическое
решение из запроса. Слабый дневной результат окажется выше сильного ночного —
это главный обсуждаемый trade-off. Без schedule metadata C3 недоступен;
C4 умеет мягко искать «дневные смены» по тексту и остаётся доступным.

Для C2 fixture quality называется `card_completeness`: демонстрационный числовой
балл полноты карточки, не оценка работника, работодателя или вероятности найма.
Формула насыщения та же. На реальном источнике пользователь подставляет свой
осмысленный показатель либо выбирает freshness-only. Поле и смысл не изобретаются
по случайным значениям `_source`.

у автоматического spelling. Все цели должны существовать в role/skill vocabulary.

`уборщик` без указания объекта — ambiguous recognition, не автоматически
«уборщик помещений». Для трёх правил с этой целью обязателен контекст помещений:
`уборшик офиса`, `e,jhobr офиса`, `uborshik офиса`; без контекста — abstention.
Весь набор не должен обходить downstream ambiguity только потому, что запись curated.

Дополнительные ≥10 правил включают комплектовщик, фасовщик, упаковщик,
электромонтёр, шиномонтажник, мерчандайзер, разнорабочий, арматурщик, сантехник,
посудомойщик. Обязательные пары: `комплектовшик→комплектовщик`,
`фасовшик→фасовщик`, `упаковшик→упаковщик`, `электромантер→электромонтёр`,
`шиномонтажнек→шиномонтажник`, `мерчендайзер→мерчандайзер`,
`разнарабочий→разнорабочий`, `арматуршик→арматурщик`, `сантехнек→сантехник`,
`пасудомойщик→посудомойщик`. Для каждой нужен контрпример; это курируемые
демонстрационные ошибки, не утверждение их частотности у реальных пользователей.

Layout channel допускает клавиши пунктуации `[];',.` **только** внутри keyboard
span, если обратная таблица даёт целую разрешённую русскую форму (`e,jhobr`).
Alphabetic-only ограничение продолжает действовать для автоматического spelling.
Защищённые технические обозначения и числовые spans проверяются до layout:
`.NET`, `2/2`, `B`, `C`, `СЕ`, `ЧПУ` не меняются. Никакого глобального удаления пунктуации.

Для C5 по-прежнему максимум два исправленных spans, одна полная строка, без каскадов.
Две разные правдоподобные роли у одного span → abstain всего rewrite.
Curated rule снабжается context predicates, а не получает право всегда побеждать ambiguity.

## 8. Вакансии и контрастные группы

≥96 карточек: минимум 10 на каждое из восьми семейств и 16 дополнительных edge cases.
Карточки короткие, но реалистичные: разные title/description, города, графики,
роль/оборудование, опыт, даты, nullable quality, category/stable id для C3.
У всех fictional ids, компаний и адресов нет привязки к реальным людям/работодателям.
Не заполнять корпус копиями одного шаблона с заменой двух слов.

Обязательные контрасты (расширить до ≥32 групп с expected rationale):

- Грузчик и водитель погрузчика; оба на складе, разные профессии.
- Комплектовщик со сканером ТСД и грузчик, в описании которого упомянуты комплектовщики.
- Кладовщик с инвентаризацией и сборщик заказов без учётных обязанностей.
- Оператор ЧПУ и наладчик ЧПУ; одинаковое оборудование, разные функции.
- Водитель B, C и CE; совпадение «водитель» не подтверждает категорию.
- Сварщик полуавтомата и электрогазосварщик; смежность не безусловная эквивалентность.
- Повар и помощник повара; помощник не становится самостоятельным поваром через alias.
- Кассир и продавец-кассир; разные доли обязанностей, нельзя потерять full role span.
- Охранник с удостоверением и контролёр без такого требования.
- Уборщица помещений, дворник и горничная с похожими словами «уборка».
- Работа без опыта и вакансия с обязательным опытом, где фраза «без опыта» находится
  в отрицательном контексте «кандидаты без опыта не рассматриваются».
- Проживание предоставляется и «проживание не предоставляется»: query matching по
  одному слову не доказательство условия; помеченный false-positive challenge.
- Вахта 30/30 против обычной смены 2/2; нельзя спутать циклы.
- Пара одинаково релевантных карточек разного возраста, missing/future date.
- Новый слабый текст против старого сильного; extreme/missing quality.
- Дневной слабый результат против ночного сильного для обсуждения C3.

Qualification и отрицания в текстах документов не интерпретируются как юридическая
проверка. Синтетический сервер возвращает контролируемый порядок и score, а не BM25.
Expected parse/DSL/ranking arithmetic и human relevance rationale хранятся раздельно.

## 9. Приёмка содержимого и перенос

Локально проверяются полнота инвентаря, уникальность ids/forms после нормализации,
все referenced concepts, directed rewrites и context predicates, отсутствие cycles,
защита категорий/разрядов/графиков, keyword boundaries и отсутствие ложного synonym
между смежными профессиями. Каждому расширению требуется positive и counterexample.
Контентные тесты должны поймать «наладчик=оператор», «грузчик=водитель погрузчика»,
«без проживания→проживание», потерю CE и исправление 2/2.

Полный blueprint не требует production данных, OpenSearch или исследования
частотности. Для переноса пользователь подставляет mapping/поля/boosts,
при желании редактирует готовый словарь, а не создаёт его вместо исполнителя.
Все UI-подписи notebook, карточки и основной query pack — по-русски.
Прежние иностранные примеры остаются отдельным regression pack.
