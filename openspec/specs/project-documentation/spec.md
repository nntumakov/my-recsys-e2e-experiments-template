# project-documentation Specification

## Purpose
Дать читателю краткое описание устройства проекта, исполняемый пример
и проверяемые инструкции разработки и обновления публичной ветки.

## Requirements

### Requirement: Concise architectural description
Текущая документация SHALL объяснять назначение проекта, поток данных,
владение состоянием и существенные отказы без повторяющихся вводных и истории
согласования. Инструкции SHALL ссылаться на исполняемые конфиги и примеры.

#### Scenario: Understand and run the example
- **WHEN** читатель открывает README и архитектуру
- **THEN** он находит Python-only пример, Hydra-композицию, registry, PipelineData,
  ветвление/RRF, метрики и сохранение результата

### Requirement: Preserve implementation and useful comments
Редактура SHALL сохранять структуру проекта и исполняемое поведение.
Комментарии SHALL объяснять ограничения и причины решений; сведения о версиях,
форматах, атомарности и проверенных результатах SHALL сохраняться.

#### Scenario: Verify the editorial diff
- **WHEN** сравниваются исходное и итоговое деревья
- **THEN** существующие пути сохраняются, Python AST без docstrings, YAML-значения
  и код notebook не меняются; проверки и документированные команды проходят

### Requirement: Separate publication branch
CONTRIBUTING SHALL описывать публикационную ветку и обычную синхронизацию с GitHub
без слияния независимых корней и автоматического переписывания удалённой истории.

#### Scenario: Prepare a GitHub update
- **WHEN** сопровождающий следует инструкции обновления
- **THEN** он проверяет diff, выполняет gates и обновляет только публикационную
  ветку; master и внутренняя история остаются отдельно
