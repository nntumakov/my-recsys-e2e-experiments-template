## Context

CompareExperiment уже владеет независимым исполнением case/pipeline, NDCG и
ComparisonArtifact. FieldScoreExtractor переносит поле в score, TopK ограничивает
выдачу без сортировки. Не хватает только явного ordering transformer.

## Goals / Non-Goals

Цель — показать полноценное локальное исследование ranking на обычном Python
с Hydra-композицией. Это ранжирование заданных кандидатов, не offline имитация
OpenSearch и не новый search backend. Существующие поисковые default не меняются.

## Decisions

- Добавить ScoreSortTransformer рядом с TopK; ответственность ограничена порядком
  по готовому score. Проверять всю коллекцию перед заменой, stable descending sort.
- Хранить вымышленные кандидаты и judgments в отдельной Hydra config group;
  общий ranking config задаёт registry, параметры и три именованных pipelines.
- Для RRF использовать полные отсортированные ветки, затем общий TopK. Признаки
  разных шкал не складываются напрямую.
- Python-пример использует Compose API и instantiate того же experiment. CLI
  использует src.run с отдельным config root. Новых runners/export formats нет.
- OpenSpec хранит новые изменения; технические объяснения остаются в architecture,
  термины — в CONTEXT, evidence — в development. Старые specs не мигрируют механически.

## Risks / Trade-offs

Синтетические признаки и три запроса не подтверждают качество на рынке вакансий.
RRF может ухудшить отдельный запрос: walkthrough показывает фактические результаты
всех вариантов, без автоматического выбора победителя. Стабильность ties зависит
от исходного порядка кандидатов и порядка веток, заданных в конфиге.

## Migration Plan

Добавление совместимо с существующими сценариями. Старый 001-comparison остаётся
доступен; новый пример получает отдельный конфиг. Подробные рабочие команды из
README перемещаются в docs/usage.md с исправлением относительных ссылок.
